1 概述

1.1 文档概述

   本次“基于区块链的试验数据存证原型软件”测试报告旨在系统性地阐述和
总结针对该原型软件所开展的全面测试活动。本次测试严格依据《基于区块链的
试验数据存证原型软件测试大纲》和《基于区块链的试验数据存证原型软件测试
细则》等规范性文件，由星网应用院组织相关测试单位共同实施完成。
   测试工作的核心目标在于全面验证该原型软件的各项功能、性能指标及其在
特定运行环境下的适应性与稳定性。功能测试聚焦于确认软件核心存证流程的正
确性，包括但不限于试验数据的哈希值计算、区块链交易生成与发送、数据上链
存证、链上存证信息查询与验证等关键功能模块，确保其业务逻辑符合设计预期。
性能测试则重点评估软件在处理不同规模、不同并发压力下的数据存证请求时的
响应时间、吞吐量及资源利用率，检验其处理效率是否满足原型阶段的性能基准。
环境适应性测试旨在验证软件在规定的软硬件基础环境（如不同操作系统版本、
数据库配置、网络条件）中能否稳定、可靠地运行。
   本原型软件作为“卫星互联网试验数据可信管理平台”的前期关键技术验证
载体，属于高可信软件与数据安全类产品。该软件采用分层、松耦合的现代化软
件架构，其技术核心在于运用 Hyperledger Fabric 联盟链框架及其附带的 Raft 共
识算法与 HASH 算法，确保存证数据的不可篡改性与交易终局性。该软件旨在
为科研试验等关键业务领域提供全生命周期的可信数据存证与溯源服务，有效防
范数据在生成、流转与存储过程中可能遭遇的篡改与抵赖风险。
   该原型软件在架构上清晰划分为五个层次：1) 前端服务层：基于 Vue 3 生
态（Vue Router, Pinia, Element Plus）构建用户界面，并利用 Apache ECharts 进行
数据可视化；2) 接口服务层：遵循 Restful API 标准，提供 JWT 认证并集成 Swagger
UI 用于接口文档化管理；3) 后台服务层：采用 Python（Django, Pandas）与 Golang
（Gin, Logrus）混合技术栈处理核心业务逻辑；4) 区块链网络层：以 Hyperledger
Fabric 为核心，实现数据的分布式账本记录；5) 数据持久层：综合运用 IPFS、

1.2 系统概述

  本产品是面向分布式外场试验与应用系统协同场景的“试验数据可信管理平
台”，以联盟链为核心，实现试验数据从产生、导入、存证、查询到审计的全流



                      6
程可信管理。其设计目标是解决外场试验中“数据分散、来源不明、格式不一、
过程不可查、结果不可证”等关键问题，为试验活动提供高可信度的数据基础保
障。
  系统总体架构采用“主链 + 多子链”的分层联盟链模式，实现不同试验域、
不同数据类型、不同设备来源之间的数据隔离、共享与可信交互。主链负责全局
索引、跨链锚定与策略统一管理，子链承担业务域内的存证写入与查询服务，从
而构成既分布式又可控的链式数据管理体系。
  本系统的主要技术特性包括：
  1. 多域链构建能力
  支持在同一平台中构建多条业务子链，通过链级隔离实现不同来源、不同密
级、不同用途数据的独立管理，同时通过主链实现跨链锚定与统一调度。
  2. 数据可信存证与校验能力
  系统通过对试验任务数据、终端运行日志、任务规划信息等生成哈希指纹，
并写入区块链，实现数据的“唯一性、不可篡改、可验证”。
  提供数据完整性校验与篡改检测能力，可面向全链路实现“谁在什么时间对
什么数据做了什么操作”的完整追溯。
  3. 灵活的查询与检索服务
  支持按任务编号、终端编号、时间范围、操作类型等多维度查询链上记录；
适用于试验结果验证、异常回溯、指挥调度分析等场景。
  4. 完备的权限与角色管理机制
  支持系统管理员、主链用户、子链用户等多类角色，对链管理、数据写入、
数据查询等操作进行细粒度授权，并提供用户会话有效期控制与行为审计能力。
  5. 智能合约管理能力
  支持智能合约（链码）的部署、更新、调用与运行状态监控，支持通过合约
实现数据冲突检测等逻辑，使系统管理方式可复用、可升级。
  6. 多类接口接入能力
  系统支持终端管理套件、自动化测试系统、数字化联合仿真系统等多类型接
口，可处理终端状态、日志、任务规划信息等结构化或半结构化数据，实现与其
他系统协同作业。




                    7
  7. 面向性能指标的处理能力
  系统整体性能满足大规模试验场景的要求：
     上链吞吐量≥2000 TPS

4 技术要求

4.1 功能要求

4.1.1 基于分层联盟链的区块链管理功能

4.1.1.1 分层多域联盟链构建

   （1）具备分层多域联盟链构建功能，分为主链和子链两层，不同种类数据
可组成多域区块链并加入联盟；
   （2）具备跨链数据交互功能，支持主链与子链之间的数据交互。

4.1.1.2 用户访问控制与权限管理

   （1）具备角色设置功能，支持系统管理员、主链用户、子链用户设置；
   （2）具备身份认证功能，支持用户密码设置，登录认证；
   （3）支持用户会话的有效期管理；
   （4）具备用户操作日志审计功能，支持对用户的访问记录追溯。

4.1.1.3 区块链生命周期管理

   （1）具备区块链创建、新增区块和销毁等管理操作；

4.1.1.4 共识机制与智能合约管理

7.1 测试总体原则与分析方法

  为确保证据充分、分析严谨、结论可靠，本章节的测试实施与符合性分析遵
循以下总体原则和方法：
  全覆盖映射设计：每个测试用例均直接、唯一地对应《研制要求》中的特定
条款，确保所有技术要求被 100%覆盖，测试结论可明确追溯至需求源头，为符
合性分析提供根本依据。
  标准化用例呈现：采用统一格式的测试用例表（包含测试用例名称、技术要
求、测试条件、测试步骤、合格判据及测试记录等关键要素）来规范测试执行与
记录过程，确保测试活动规范一致、结果可追溯、过程可复现。
  逻辑化执行路径：测试执行路径遵循由简至繁、由单模块到多集成的逻辑。
功能测试从基础能力（如创建存证链、数据导入）逐步过渡到复杂行为（如冲突
检测、全链路追溯）；性能测试则从典型负载场景扩展至极限压力场景，确保测
试结果全面且有代表性。
  客观化符合性判定：每个测试用例均预设明确、量化的“合格判据”。测试
结果将严格对照判据，得出“符合”或“不符合”的客观结论，杜绝主观判断，
确保符合性分析的公正性与科学性。
  完整性记录保障：测试记录作为符合性判定的直接证据，被列为必需环节，

9 测试保障条件

9.1 数据记录要求

  测试数据记录是测试报告的原始根据，数据记录必须真实反映软件的客观情
况。
  a）使用统一的记录表，填写测试日期、项目、版本、结果；
  b）对未通过的项目简单备注原因；
  c）记录由测试人员签名确认。


9.2 测试报告要求

  测试报告应总结软件测试过程的结果，提供软件质量的评估结论，并依据测
试大纲和测试细则说明的测试日期、条件、步骤、人员及测试结论。应根据测试
大纲和测试细则要求，报告应包括详细的测试记录，明确测试人员、记录人员和
检验人员的签字，确保记录的有效行吧。报告结构包括概述、技术要求、测试环
境、测试软件、测试组织与实施、测试结果、问题闭环、测试结论以及附录中的
测试记录，其中无测试人员、记录人员及检测人员签字无效。

11 测试组织和计划

11.1 测试组织管理

  试验终端故障建模分析原型软件的出厂测试工作由承研单位北京理工大学
组织实施。测试参与人员分为测试组和记录组。
  测试组负责测试场地搭建、提供测试程序、定位故障问题等，按需安排具体
测试操作人员。记录组负责协调测试、记录测试数据、复核测试结果并记录现场
问题。出厂测试形成出厂测试总结报告。


11.2 测试地点

  本次测试涉及的测试地点为星网应用院 10 层测试机房，测试环境为统一测
试环境。


11.3 测试计划

  测试阶段包括测试用例设计、测试环境搭建到功能、性能、接口、流程测试
和回归测试等环节。在执行测试用例时，测试人员会系统性地验证软件的各项功
能和性能，同时记录并跟踪发现的缺陷，以便及时与开发团队沟通并推动修复。
  各项测试将确保软件在真实环境下的表现符合预期，最终由用户确认测试结
果以保障本软件的交付质量。测试中介与报告撰写阶段，团队将汇总测是结果，
分析项目中的问题和改进空间。通过这一系列有序的活动，有效保障项目质量。
